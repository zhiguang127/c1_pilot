“引用校验失败”只是自动发现的缺测/null/零 RHR 引用、缺少具体证据或引用编号问题，**不是医学适用性错误率，也不是完整 Evidence Correctness**。通过引用存在性检查也不证明时间范围、数值、来源或条件推理正确。保留模型原始标签和解释，不用另一个 LLM 修标签。解析状态与证据状态分开，避免因证据问题把整个三分类结果悄悄丢掉。

PHIA 和 Orchestrator 在这个受控问题上没有选择数据工具；不能因为架构提供工具，就声称本例使用了工具或工具有收益。Parallel 和组合对照保存了真实代码、计算结果、错误、官方调试与子 Agent 输出。各方法当前没有诊断性子 Agent 错误，但 Health Coach 的原有角色对固定 ID 分类并不天然适配；这种任务适配局限也保留在私人原始轨迹中。

Controlled 设置只把固定候选正文作为 search 的来源结果，DataCommons 明示不可用，不进行额外联网医学查询。原官方 few-shot 与模型先验仍存在，所以不能宣称完全相同的内部知识预算。工具可访问完整 42 行；不保证官方路由后的每次内部消息都原样包含所有行，实际消息/上下文在私人日志可审计。

主要修正是：精确引用 ID 的输出要求；单候选失败隔离；标签解析和证据校验分开；确定性提取单个 fenced JSON（不增加模型推理）；OneTwo Responses 到受计量 Chat Completions 的显式 transport bridge；在 SDK 请求入口拒绝漏计路由；真实输入的空活动/人口表只补官方字段列头、仍为零行；记录子 Agent 错误，避免合成文字掩盖失败；缓存命中保留 usage 供逻辑成本审计。没有修改官方源码、虚构人类标注或补造缺失健康值。

中间失败版本保存完整私有请求/响应/工具轨迹、配置与代码哈希，以及修正说明；并非每次临时修改都单独提交源码快照，因此这些中间版本只作工程历史，不作正式性能基线。最终代码由 PR 提交与最新协议冻结；正式多参与者实验前仍需固定最终参数与人工确认条件。
