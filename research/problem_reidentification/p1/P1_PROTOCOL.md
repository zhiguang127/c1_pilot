# P1：推荐优先级监督信号可识别性协议

版本：p1-v1；日期：2026-10-16。仅评估 P1，不继续 C1/C2 或 M1/M2，不设计推荐算法，不训练或调用标注模型。

**问题**：同一真实纵向健康记录支持多条健康知识时，人能否根据记录和来源条件，稳定判断推荐优先关系？“适用”“应优先推荐”“临床获益”是不同判断。相关性标签不能替代优先级标签。

允许结果是优先级不存在、仅有局部优先、合理并列，或缺少症状、目标等信息而不可识别。本研究不以支持新算法挑战为成功条件。

## 数据和取样

原始数据仅从 [PMData 官方 OSF](https://osf.io/vx4bk/) 下载。数据集说明见 [Simula](https://datasets.simula.no/pmdata/)，论文 DOI：[10.1145/3339825.3394926](https://doi.org/10.1145/3339825.3394926)。遵守原始 CC BY-NC 4.0；不采信第三方镜像的不同许可。研究对象是历史记录上的教育知识判断，不是给参与者发送健康建议。

取样规则在 `sampling_plan.json` 固定，先于正式案例导入和任何人工标签。它是本仓库内的事先方案，不宣称外部注册。

- 使用官方目录中的全部参与者。每人从 2019-11-01 起取前三个连续、不重叠的 42 天区块；每区块前 28 天为基线，后 14 天为当前窗，评估时点为第 42 天末。只提供截至此时的记录。
- 仅以技术覆盖决定纳入：基线和当前窗各至少 7 天有至少一个导入指标的记录。不以异常幅度、主题数量、可排序性或标签筛选。零活动的记录值不证明已佩戴。
- 目标 30–50 个案例，最多 48 个。数量不足时标记 `BLOCKED_REAL_DATA`，保留全部排除记录，不修改规则以补足期望结果。
- 导入明确主睡眠的时长和钟点、原始 sleep log 类型与 infoCode、RHR，以及设备轻度/中度/高度活动分钟和 sedentary 分钟。保留每日序列、缺测和质量标记；不填补、不插值、不将未知当 0。classic 睡眠日志不证明 Light/Deep/REM 分期可用。
- 同日重复主睡眠日志只在 logId 和全部导入睡眠字段相同的情况下折叠；不同的未导入字段可来自导出修订。若导入字段或 logId 冲突，该日睡眠字段全部置为未知并明确标记，不选择最长或最符合预期的一条。
- 源不存在的文件保留 `absent_at_source`。RHR=0 原值不改，但标记为不能作生理解释；非零 sleep infoCode 保留并提示设备质量待核实。设备活动等级不等于独立核实的强度；sedentary 不等于坐姿或连续久坐。时区、佩戴时长和设备变更未知，不推断 DST 或临床异常。
- 仅使用论文第 3 节报告的成年人群范围作为群体背景；不推测个体年龄。未导入自报告、症状、疾病、药物、目标和偏好；评审可以明确指出这些缺口。后续增加信息需另一个版本，不覆盖本轮。

一个案例不是一个独立受试者。同人最多三个窗口，按 `subject_id` 保留聚类。只报告描述性比例和按参与者分解；不把 48 个窗口或 240 个候选判断当作独立样本计算置信区间或显著性。

## 候选知识与选择偏差

从冻结的 96 条知识中复用五条跨已测领域的候选：K006、K017、K041、K083、K094，涉及睡眠时长解释、作息、日常活动、RHR 记录和睡眠估计。所有案例使用同一五条面板，不经检索、不看旧标签和方法表现，不人为保证两条以上适用。候选面板在完整导入前固定。

这是一个**固定候选面板上的初始可行性研究**。它不是全部知识库上的优先级分布估计；相近来源、教育性条目和候选覆盖可能限制结果。若适用候选不足，直接报告，不替换成“更容易产生排序”的候选。换面板必须新建版本并报告原因。

每条保留独立正文、来源链接、适用/不适用条件、原快照日期、支持锚点和快照 SHA-256。原 `verified` 是抓取及 LLM 复核状态，不能写成人类或临床核验。主评审至少一人具有相关健康知识审查背景，裁决者亦须具备；评审发现来源不支持的内容时记录 `source_scope`，暂停该问题的实质结论，不自动改成不适用。当前设备文档未必完整描述 2019 年算法，也可构成信息不足。源更新不覆盖冻结快照。

## 人工程序与盲法

1. 先招募 A/B 两名不同人工评审和第三方 C，记录匿名 person_id、专业背景、角色和独立性声明；至少一名主评审和 C 具备相关健康知识审查能力。模板默认不声明任何人为已招募。
2. 用不进入正式样本的真实案例培训术语；目前无已完成培训，正式标签前应登记培训记录。不得使用本轮正式案例反复磨合直到高一致。校准中改规范须新版本且在正式评审前冻结。
3. 冻结案例、面板、协议、指南和代码校验值。每位评审有不同案例顺序和候选顺序；在隔离文件夹中仅发其自己的卡片、指南和空表。
4. 卡片只显示日序列、已提供背景、缺测/质量信息、候选正文与来源条件。隐藏原参与者 ID、绝对日期、稳定 subject_id、构造/筛选原因、知识 ID、旧标签、模型输出、检索分数及另一评审意见。相对日号保留时间顺序，星期保留日历信息但不代表工作日。
5. A/B 独立完成所有案例，不接触对方材料，不查看整个仓库、映射或数据发布目录。评审后锁定原始提交及完成时间，再生成分歧队列。随机顺序不保证人类无法从相似记录识别同一人，需报告此限制。
6. C 获得两份独立判断、各自原卡片和候选映射。C 依据记录与来源裁决全部语义分歧，保留其独立完整判断与分歧原因，不采用多数票、平均值或强制 Top-1。并列和信息不足均是有效裁决。C 不能改写 A/B 原记录。

原始数据、HMAC 密钥和身份映射仅在忽略的 `local/`。共享发布仅保留伪匿名 ID、相对时间及白名单字段。这是**伪匿名化**，不能保证公开可穿戴序列无法重新识别；不得宣称不可逆匿名。不要向评审发整个仓库或 `private/`。

## 判断与分析计划

详见 `P1_ANNOTATION_GUIDE.md`。逐候选先判断 `applicable / not_applicable / insufficient_information`，逐对比较全部明确适用候选，记录优先、合理并列、不可比较或缺信息。每个判断有具体观测引用、来源条件引用和理由。

case `priority` 描述已确定适用集合：`clear`（所有对均可判断且至少一个严格优先）、`partial`（部分严格优先，其余不可比/缺信息）、`none`（无严格优先）、`insufficient_information`（无严格优先且有缺信息对）、`not_comparable`（不足两个明确适用）。`top_outcome` 分别记录唯一最优、并列最优、未能形成最优集合、信息不足、不足两个可比候选。任何候选适用性未知时，不把其他候选声明为面板唯一/并列最优。不能以“没有差异证据”填写合理并列。

预定报告：

- A/B 各自适用性分布；完整裁决后的最终适用性分布，分母是实际候选数。
- `clear` 且面板最优判断不缺信息的案例比例，分母分别用全部案例和至少两条适用的案例；同时单列 `partial`、`none`、`not_comparable`。
- 唯一最优、并列最优、未形成最优集合、信息不足及不可比的完整分布；可确定最优集合比例、任意合理并列比例，以及任一适用/比较判断缺信息的案例比例。各分母明确区分。
- 裁决前 A/B 的候选适用性、case priority、top outcome 的 exact agreement、名义 Cohen's kappa 与混淆计数；另报完整 case 语义一致率和最优集合一致率。类别无序，不使用线性加权 kappa。
- pairwise kappa 仅对双方均确定适用的共同候选对计算，明确样本数，不能掩盖适用集合分歧；完整 case 一致率会计入这些分歧。标签单一导致机会一致率为 1 时 kappa 为 null，并解释原因。
- C 实际登记的分歧原因分布、各评审实际登记的缺失信息类型。理由文本保留；代码不声称已理解或核实理由的医学正确性。

部分提交可输出注明覆盖率的 A/B 配对描述；缺失不填 0，不仅筛选一致样本报告最终比例。全量双评和分歧裁决完成前，不输出最终比例或 P1 结论。没有人工提交时 agreement、kappa 和研究比例全部为 null。

不设用于“证明 P1 成立”的事后阈值。不因低一致率、并列过多或缺信息而删样本。可靠监督需同时审查可判断覆盖、原始一致性、证据依据与参与者差异；高 kappa 不等于医学正确或新算法必要性。

## 版本、状态和冻结边界

`BLOCKED_REAL_DATA`：真实数据不可用或按原规则不足 30–50 例；工程准备仍可交付。`PREPARED_NOT_ANNOTATED`：真实案例及卡片已备好，无真实人工标签。之后可为 `PARTIALLY_ANNOTATED`、`AWAITING_ADJUDICATION`、`ANNOTATED`；最后一个状态只是材料完整，不表示假设得到支持。

所有新文件在本目录内。既有 C1 数据、冻结清单、标注、代码及实验结果一律只读。每次发布用新目录，校验失败立即停止；原始记录与评审提交不覆盖。单元测试使用明确命名的人工构造夹具，只验证软件，不进入数据发布或研究统计。
