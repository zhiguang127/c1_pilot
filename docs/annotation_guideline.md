# Relevance annotation guideline

## 1. 标注任务与证据边界

标注的是 `(D_t, k_j)`：在当前 14 天及此前 baseline 的原始可穿戴记录下，这条知识是否是理解实际观察、记录变化或考虑日常健康习惯的相关候选。不是标注疾病、治疗、最终推荐优先级或用户一定要采取的行动。

材料：原始日序列 / 时间段、缺测与质量信息、已复核的 deterministic statistics、知识的最终正文与来源适用条件。年龄 / 时区 / 设备只在同等条件下提供。主依据为原始数据和实际知识内容，不能依据 case intended pattern、summary、PHIA、Evidence、query、retrieval score 或检索结果。

标注员界面不显示 case_type、A/B/C、difficulty、matched_group、designer_notes、期望 topic、生成表示或方法名称。匿名随机 case/item 顺序，保留后台 ID 用于追溯。不得先看 top-k 再给其余 pair 默认为 0；要双人独立检查全部 2304 pairs。

## 2. 三级 relevance

| Label | 定义 | 必须能给出的理由 |
| --- | --- | --- |
| 0 = irrelevant | 不针对当前实际观察；主要适用条件不满足或与观察相矛盾；只能靠未知症状 / 诊断 / 未记录强度建立联系；或只是人人都适用、对本 case 没有具体解释价值的常识 | 指出条件不符、证据缺口或仅表面词汇相似；不能仅说“系统没有召回” |
| 1 = relevant candidate | 与已观察事实存在具体、受正文支持的关系，可用于背景理解或数据解释，但不是最直接覆盖当前核心模式；或正文包含多个条件分支，其中只有一个独立、实际有用的分支被支持 | 至少一个原始事实和正文条件的对应；不依赖虚构上下文 |
| 2 = strongly relevant candidate | 正文的核心主题直接覆盖一个明确、可靠且当前重要的观测模式，主要适用条件均由数据 / 已提供上下文支持；不需要额外医学假设 | 给出支持核心模式的日期 / 数值 / 区间及正文定位；说明为何比背景知识直接 |

relevance=2 不意味着紧急或“应该执行”。多个 item 可以为 2，也可没有 2；不能用固定每 case 正例配额。relevance=1 也不是“不确定”的垃圾桶。未知且影响裁决时先 needs_review；可裁决后才给 0/1/2。

当一个一般健康 item 的确直接解释实际 pattern，即便适用人群宽，也可以为 2；宽泛不自动降级。相反，健康内容真实、包含 sleep 或 heart rate 关键词，本身不足以获得 1。对同 topic 的近邻，逐条依据正文条件判断，不能整组复制标签。

## 3. 边界规则

| 情况 | 规则 |
| --- | --- |
| 一个孤立值 vs 持续变化 | 原始频率与连续性分别检查。要求持续的正文不能用一个点支持；解释孤立读数限度的正文可能直接相关。不能从统计显著性替代健康条件 |
| baseline 相对变化 | 同设备、同指标定义和覆盖可比才可使用个人比较；总体常见值不取消个人变化，也不能证明个人变化有害 |
| 当前持续 vs 已回归 | 分别依据 window 后段及整窗历史；持续问题条目在已回归 case 中可能是 0 或仅历史背景 1，恢复 / 记录类可能更直接；不能把过去发生过一律当作现在仍发生 |
| 规律但晚的钟点 | 晚本身不等于不规律、睡眠不足或疾病；需检查时长、分布和正文是否有特定已知条件 |
| 工作日 / 周末差异 | 看原始 date 和分组，不能由总体均值猜差异；weekday 不自动等于人的工作日 |
| 多变量共变 | 只说明观测同期 / 对齐，不承诺因果；如果正文只支持单变量，其相关性可以不受共变改变；没有 source-backed conjunction 不强制组间 gold 不同 |
| 未知活动强度 | 活动时长不自动成为 moderate-intensity minutes；只有明确记录的强度才可应用强度阈值知识 |
| 低移动 vs 坐姿 | 没有姿态证据时不声称真实坐姿；可使用少动的通用教育，不能据每日总量声称有长连续段 |
| HRV / RHR | 只支持测量解释、个人记录和受支持的趋势理解；不由其推断 stress、infection、诊断或特定治疗；RHR 和 sleeping HR 不替换 |
| 缺测 | null 不是 0；覆盖不足的低 steps 不能支持低活动结论。解释缺测的知识可能相关，但不能为所有完整数据 case 自动给 1 |
| 症状 / 轮班 / 时差未知 | 不把未知当作“没有”或“存在”。要求该上下文的特定条目不可据 D_t 支持；有独立一般分支时仅对该分支判断 |
| 条件部分满足 | 核心必要条件缺失时不是 2；正文若只有一个依赖未满足条件的主张则 0，不能自动标 1 |
| 阈值附近与测量误差 | 不根据小数后一位制造确定性。记录边界和质量；缺少来源 / 误差说明时 needs_review，不发明容差范围 |
| 所有指标基本稳定 | 不默认健康维护类都相关；只保留对实际观察有具体解释价值的知识。可出现全零 case，最终由全文与数据决定 |

从原始数据不能判断某种健康状态，不等于该人没有这种状态。给 0 的含义是此 benchmark 的 evidence 不足以使该 candidate 相关，而不是证明医学上不适用。

## 4. 标注记录与分歧处理

每名标注员独立保存 `case_id,knowledge_id,annotator_id,relevance,status,raw_data_evidence,item_condition_evidence,rationale`。原始证据例：`window_daily[2026-04-01..2026-04-07].metrics.steps`；知识条件证据记录正文句子 / source_locator。说明是观测事实、数学转换还是未知上下文，不能写“Evidence 说……”。

status 为 labeled 或 needs_review；needs_review 的 relevance 留空。最终 relevance_labels.csv 只包含完成裁决的 0/1/2。不能把空值用 0 补齐。数据自相矛盾、知识没有出处、正文多主题或条件含糊时，先反馈数据 / corpus 问题，而不是强行标注。

先在不属于 24 条主样本的 2-3 个练习 case 上校准定义，含 0/1/2 和缺测情形；练习不进入正式统计，也不看模型输出。正式阶段两个独立标注员，其中至少一人具有相应健康知识审查能力；第三人或共同会议依据原始证据裁决，保存裁决理由及版本。

报告原始 exact agreement、0/1/2 confusion matrix、线性 weighted Cohen kappa，并解释高度偏斜的零标签会影响 kappa。也报告非零判定的分歧率、matched groups 和各类型的分歧。不要只用整体高一致率掩盖正例分歧。可把非零/零争议过多或 kappa 很低作为返工信号，但 pilot 的样本量和标签分布决定这些读数的限度，不把一个任意阈值称为通用合格线。

裁决前不能把两人平均得到 0.5 / 1.5 当 gold；不能用模型多数票替代独立人工 gold。先冻结 corpus 和数据，在方法比较前完成全部裁决。冻结后内容修改必须增版、重标受影响 pair，重新跑所有比较条件；不根据获胜方法挑 pair。

## 5. 准备完成的检查

检查 24 个真实 case ID、96 个 verified item ID、2304 个唯一 pair，无空标签 / 未裁决记录；日期和统计通过复核；标注视图不含设计 / 模型信息。审查主要主题是否真的有条件相近负例、是否有等级 2、是否有真实全零 case；这些是诊断读数，不能为了满足配额改标。全零 case 如果不存在，明确报告不能衡量 case 级 abstention，仍可测 pair / top-k 的误检。

设计表中的 A、B、C 不能替代这些检查。发现 matched pair 的 gold 相同，允许且应记录；它可能说明该信息不是本 corpus 的检索必要条件，而不是标注错误。
